# DEVORKS+ — VK-бот (перенос с Telegram)

Полный перенос школьного Telegram-бота DEVORKS+ на платформу **ВКонтакте**
«точь-в-точь»: расписания, ДЗ, классы, анонимки, погода, AI (DEVORKS+AI на Groq),
таймеры, уведомления, панель админа класса и панель разработчика — вся логика
сохранена. Telegram Stars заменены внутренней валютой **«штуки»**
(1 штука = 1 рубль) с оплатой **самозанятому по QR-коду или ссылке** и
выдачей **официальных чеков** (НПД / «Мой налог» / Т-Банк).

## Что нового в этой сборке (ТЗ DEVORKS+)

### 0. Общее переименование и работа в беседах (групповых чатах VK)

* Бот по всей системе переименован в **DEVORKS+** (приветствия, шапка меню,
  справка, системные уведомления). AI-модуль теперь называется **DEVORKS+AI**
  (старое имя кнопки «🤖 DEVO+ai» продолжает работать для совместимости).
* **Бот полноценно работает в беседах** (peer_id > 2000000000), а не только в ЛС:
  * персональные данные, настройки и балансы «штук» хранятся за **from_id**
    (пользователем), а ответы отправляются в текущий чат (**peer_id**);
  * из текста команд автоматически вырезается системное упоминание бота
    вида `[clubXXXXX|@group_name]` — `[club123|@devorks] /start`
    распознаётся как `/start`;
  * у каждого участника беседы — свой независимый контекст диалога
    (ConversationHandler ведёт состояние на пару «чат + пользователь»);
  * в беседах бот реагирует только на команды и клики по кнопкам своего
    меню — обычные сообщения чата не комментирует (без спама);
  * при нехватке прав бота в беседе (чтение/отправка сообщений) ошибка
    фиксируется в логах и разработчику отправляется уведомление.

> Чтобы бот видел ВСЕ сообщения беседы, добавьте его в беседу и включите
> в настройках сообщества «Разрешить сообщения бесед» (Управление →
> Сообщения). Inline-кнопки под сообщениями работают в беседах «из коробки».

### 1. Сетка кнопок (2 / 3 / 4 ряда)

* По умолчанию главное меню собирается в **2 ряда**.
* В «⚙️ Настройки» добавлен пункт **«📱 Сетка кнопок»**: выбор 2 / 3 / 4
  ряда и «🔁 Вернуть как было» (сброс на стандартный вид — 2 ряда).
* Выбранная сетка сохраняется в профиле (`user.keyboard_rows`) и
  применяется при генерации любой Reply-клавиатуры пользователя.

## Что изменилось относительно Telegram-версии

| Было (Telegram) | Стало (VK) |
|---|---|
| python-telegram-bot 21.6 | собственный слой совместимости `vk_api.py` (Long Poll VK) |
| Обязательная подписка на Telegram-канал | подписка на группу ВК (`groups.isMember`) |
| Оплата Telegram Stars (XTR) | «штуки»: пополнение по QR/ссылке самозанятого, чеки НПД |
| Инвойсы/предчеки бота | код платежа `PAY-XXXX` + кнопки «Я оплатил» / «Проверить» |
| t.me-реферальные ссылки | `vk.com/write-<группа>?ref=ref_<id>` (deep-link) |

### 2. Монетизация и платные функции

* **Платные кнопки** — полный цикл управления прямо из панели
  («🛠️ Панель разработчика» → «🔒 Платные кнопки»): создание, название,
  цена в штука́х, тип (текст/ссылка), контент, **переименование и правка
  контента** существующих кнопок, смена цены, удаление. Пользователь
  покупает кнопку **один раз** — доступ навсегда (`user.purchased_buttons`).
* **Моментальная синхронизация цен/балансов** — клавиатуры строятся при каждом
  запросе из хранилища, кэши глобальных кнопок сбрасываются при каждом
  изменении из панели, цены читаются из единого `prices.json`; при правке
  `prices.json` вручную бот перечитывает файл автоматически (раз в 30 сек,
  без перезапуска). Баланс «штук» обновляется мгновенно при пополнении/списании.
* **Статистика расходов** — история переводов (кто, кому, сколько переводил)
  **удалена**. Отображаются только: 🏆 топ пользователей по сумме потраченных
  штук, 💰 общая сумма расходов всех пользователей, 👥 общее число
  зарегистрированных пользователей.

### 3. Исправления багов и логики

* **Уведомления о погоде**: рассылка включена в единый тикер уведомлений —
  сообщение приходит в установленное пользователем время
  (`weather_notification_time`) с учётом его часового пояса, один раз в день,
  с кнопкой «На 3 дня». Дубли исключены журналом отправок.
* **Настройка времени звонков**: устранено бесконечное переспрашивание
  «начало → конец». Ввод строго пошаговый (два состояния ConversationHandler:
  `EDIT_BELL_TIME` → `EDIT_BELL_END`), с валидацией формата ЧЧ:ММ и того,
  что конец не раньше начала; параметры сохраняются сразу.
* **Личные кнопки-ссылки**: корректные URL больше не отклоняются с ошибкой
  «недопустимые символы» (раньше символ «/» в любом URL браковался проверкой
  запрещённых символов). Ссылку можно вводить и без протокола
  (`vk.com/page` → `https://vk.com/page`); правка содержимого кнопки-ссылки
  проверяется как URL, а не как обычный текст.
* Стандартная логика (профиль, расписание, ДЗ, анонимки, AI, таймеры)
  сохранена и синхронизирована.

### Схема оплаты (самозанятость)

1. Пользователь открывает «🪙 Штуки» → «💳 Пополнить (QR/ссылка)» → выбирает
   пакет (100/200/500/1000 шт — пакеты настраиваются в `prices.json`, ключ
   `packs`).
2. Бот создаёт платёж с уникальным кодом `PAY-XXXX` и присылает **QR-код**
   (генерируется локально, отправляется как фото) и платёжную ссылку:
   * **Авто-режим (Т-Банк API)** — если задан `TBANK_API_TOKEN`, бот создаёт
     персональную ссылку через OpenAPI Т-Банка «Самозанятые», сам видит
     оплату (фоновая проверка раз в 30 сек) и сразу начисляет штуки; чек
     формируется банком автоматически в «Мой налог».
   * **Ручной режим** — пользователь переводит деньги по статичной ссылке/QR
     (из «Мой налог» либо из панели: «🧾 Данные самозанятого») с кодом
     платежа в комментарии, жмёт «✅ Я оплатил»; разработчик подтверждает
     в панели («💳 Платежи») и прикладывает чек.
3. После подтверждения бот начисляет штуки и отправляет **официальный чек**:
   квитанцию (номер чека, дата, сумма, ФИО/ИНН самозанятого, наименование
   услуги) и ссылку проверки чека `https://npd.nalog.ru/check/...`.

Реквизиты самозанятого (ФИО, ИНН, платёжная ссылка) задаются один раз в
панели: «🛠️ Панель разработчика» → «🧾 Данные самозанятого».

## Файлы

* `main.py` — вся бизнес-логика бота (перенос оригинала + платежи + ТЗ п.1).
* `vk_api.py` — VK Bots Long Poll + слой совместимости с python-telegram-bot
  (Update/Message/CallbackQuery/клавиатуры/ConversationHandler/JobQueue).
* `requirements.txt` — зависимости (`python-telegram-bot` больше не нужен).
* `.env.example` — шаблон переменных окружения.

Данные (users.json, classes.json и т. д.) полностью совместимы с
Telegram-версией — можно перенести существующие JSON-файлы как есть.

## Быстрый старт

1. **Создайте группу ВК** (или возьмите существующую).
2. Управление → **Работа с API** → Ключи доступа → создайте ключ с правами:
   *сообщения*, *фотографии*; в разделе «Возможности ботов» включите
   сообщения бота.
3. Узнайте числовой `VK_GROUP_ID` группы и свой `DEVELOPER_ID` (id профиля).
4. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

5. Задайте переменные окружения (см. `.env.example`):

   ```bash
   export VK_TOKEN="токен сообщества"
   export VK_GROUP_ID="12345678"
   export DEVELOPER_ID="ваш_vk_id"
   export GROQ_API_KEY="ключ_groq"
   python3 main.py
   ```

6. Напишите боту `/start` в личных сообщениях группы.

## Самозанятость и чеки: подключение

* Зарегистрируйтесь как самозанятый в приложении **«Мой налог»**.
* **Вариант А (автоматический)**: подключите сервис **Т-Банк «Самозанятые»**,
  получите API-токен и задайте `TBANK_API_TOKEN`. Бот будет сам создавать
  платёжные ссылки и подтверждать оплаты; чеки формируются автоматически.
  При смене API Т-Банка пути эндпоинтов переопределяются переменными
  `TBANK_LINK_PATH` / `TBANK_STATUS_PATH`.
* **Вариант Б (ручной)**: возьмите статичную платёжную ссылку/QR из
  «Мой налог» и вставьте её один раз в панель разработчика бота
  («🧾 Данные самозанятого» → «Изменить платёжную ссылку») — вместе с ФИО и
  ИНН для квитанций. Подтверждайте оплаты кнопкой в панели; номер чека из
  «Мой налог» можно приложить на шаге подтверждения — бот отправит его
  покупателю со ссылкой npd.nalog.ru.

## Хранение данных

Приоритет хранилищ (как в оригинале): **Supabase → MongoDB → локальные JSON**.

* Supabase: задайте `SUPABASE_URL` + `SUPABASE_KEY` (service_role!) и один раз
  выполните в SQL Editor:

  ```sql
  create table if not exists kv (
    key text primary key,
    value jsonb not null,
    updated_at timestamptz default now()
  );
  ```

* MongoDB: задайте `MONGO_URI` (+ `MONGO_DB`).
* Локально: JSON-файлы в текущей папке (или `BOT_DATA_DIR`).

## Деплой (Render / Railway / VPS)

1. Создайте Web Service из репозитория: команда запуска `python3 main.py`.
2. Переменные окружения — как в `.env.example` (в панели хостинга).
3. Keep-alive HTTP-сервер уже встроен (порт `PORT`, путь `/health`).
4. Для сохранения данных подключите диск/том и укажите `BOT_DATA_DIR`,
   либо настройте Supabase/MongoDB.
